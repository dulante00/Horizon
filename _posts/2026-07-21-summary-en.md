## [HuggingFace Releases Grabette for Robot Manipulation Data Recording](https://huggingface.co/blog/grabette) ⭐️ 7.0/10

HuggingFace has launched Grabette, an open-source system designed for standardized robot-manipulation data collection and sharing. The tool aims to address dataset fragmentation in robot learning by providing a unified data format across different hardware platforms. High-quality, standardized demonstration data is a critical bottleneck for robot imitation learning and policy training, and the field suffers from incompatible formats across different robotic setups. By offering an open, unified pipeline, Grabette could lower the barrier for researchers to contribute and share data, accelerating progress in robot learning similar to how ImageNet catalyzed computer vision. Grabette is positioned as part of HuggingFace's broader robotics ecosystem, complementing their existing LeRobot framework. The system emphasizes cross-hardware compatibility, allowing data collected from different robot arms and sensors to be stored in a consistent format suitable for downstream imitation learning pipelines.

rss · HuggingFace Blog · Jul 21, 00:00

**Background**: Robot imitation learning trains robots to perform tasks by learning from human demonstrations, similar to how large language models learn from text corpora. However, unlike text or image data that is easily shared online, robot manipulation data is hardware-specific, expensive to collect, and typically locked to particular robot models. This fragmentation makes it difficult to build large-scale, diverse datasets. Open-source frameworks like Grabette, LeRobot, and MimicLabs aim to solve this by providing standardized collection tools and data formats that work across different robotic platforms.

## [Prompt Caching + Sticky Routing: How to Cut LLM API Costs](https://openrouter.ai/blog/tutorials/prompt-caching-sticky-routing/) ⭐️ 6.0/10

OpenRouter published a tutorial explaining how prompt caching and sticky routing work together to reduce LLM API costs. The guide notes that cache reads cost 0.1x to 0.5x of fresh input tokens, but only when subsequent requests are routed to the same provider that holds the warm cache. This matters for engineers building LLM applications at scale, where repeated system prompts, tool definitions, and JSON schemas can dominate token costs on every turn. Without sticky routing, standard load balancers can unknowingly send requests to different providers, defeating the cache and silently inflating bills. The tutorial provides concrete methods to verify caching is actually working, including inspecting response metadata fields like cached_tokens. Sticky routing ensures that requests sharing the same identifier (e.g., a conversation or session ID) are consistently routed to the same backend, preserving the KV/prefill cache across turns.

rss · OpenRouter Blog · Jul 21, 00:00

**Background**: Prompt caching is a technique where LLM providers store recently processed prompt prefixes and reuse the computed attention states (KV cache) for subsequent requests, dramatically reducing both latency and cost. Standard load balancers distribute requests across multiple backend servers or providers for reliability, but this can fragment caches. Sticky (or session-affinity) routing ensures that requests sharing an identifier are always sent to the same backend, keeping the cache warm. As LLM API prices have dropped roughly 80% in the past year, prompt caching has become a key lever for further cost reduction, with some providers offering cache reads at 10–50% of normal input pricing.
